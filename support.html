Local installation and onboarding

  1. Requirements: Chrome, Node.js 22+ and a trusted copy of the source repository. At repository root run npm install, npm run test -w @saas/options-overlay, then npm run build -w @saas/options-overlay.
  2. Load unpacked: in Chrome open chrome://extensions, enable Developer mode, choose Load unpacked and select apps/options-overlay. Do not load unknown third-party ZIPs.
  3. Open a supported page: navigate to the Binance E-options section at https://www.binance.com, for example /en/eoptions; reload the tab after installing. A panel should appear if the URL matches and the page allows it.
  4. Try Free ETH: choose ETH in the overlay, inspect the expiry summary and refresh button. Free needs no account and no local server. Verify index timestamps and the public provider's figures independently.
  5. Optional sign-in: the popup is connected to http://127.0.0.1:3212 only. A developer must separately start the local API, set exact extension-origin CORS and manually create a test account using the repository README. A test account begins as Free. Do not use real payment cards or share credentials.
  6. Stop testing: choose Sign out in the popup if signed in, then select Remove on the extension's Chrome management page. For a separately created backend account, request deletion below.

Not a public installer: any generated development ZIP is for controlled local testing only. It retains a loopback-only HTTP account host permission, not a hosted HTTPS subscriber service. It is not ready for Web Store publication or unaffiliated beta testers.

Troubleshooting common issues

Nothing appears on the options page

Confirm the extension is enabled; open a supported www.binance.com E-options path, such as /en/eoptions; reload the tab. The manifest's match pattern may not cover changed routes, and Binance can change its page architecture. Make sure you loaded the correct apps/options-overlay folder.

“Data unavailable”, blank values or unexpected IV

Check connectivity and Binance's public API availability. The extension validates exchange and index timestamps and some quote fields, but the individual mark response has no per-quote freshness time. Refresh and compare against the provider. A number in the overlay is not an executable quote or a recommendation.

BTC is blocked, or Pro disappears

The Free view supports ETH only. BTC, extra rows and term analytics require a current test Pro entitlement validated through the optional local API. An expired, revoked or unavailable account service falls back to Free; signing in does not inherently grant Pro.

The popup says “Account service unavailable”

Anonymous Free should still work without a server. For deliberately created local accounts, confirm that the backend runs at 127.0.0.1:3212, the configured Chrome extension ID matches its CORS origin, and your test credentials are valid. Do not expose the loopback backend to the internet.

Can I refresh or use data offline?

Refresh requests another public market snapshot (short cached responses are possible). There is no offline historical database, guarantee of exchange uptime, live-data subscription or predictive alerting service.

Access, correction and deletion of account data

  1. No account used: if you only viewed Free ETH anonymously, remove the Chrome extension to clear extension-side settings/session storage. No Option Lens backend account was created through anonymous Free use.
  2. Local account used: send email from the account address to studionakamoto@gmail.com with subject Option Lens account deletion. Say whether you need a copy/access request, an email correction, or account deletion. Avoid all passwords, tokens, Binance API keys, government IDs and card details.
  3. Verify ownership: support may reply with a confirmation request to the registered account email, or a safer verification mechanism. Never send your password. If you no longer control the address, describe that problem so a manual privacy review can determine a safe process.
  4. Operator action: after verification, an authorized local operator can find the account by known ID and run the administrative delete-account command documented in the repository. This deletes the user and related session rows; unlinked billing webhook event IDs may remain as replay protection.
  5. Confirmation and residual data: ask for confirmation and any information about backup/log retention applicable to the specific test setup. An extension uninstall, sign-out or email alone does not guarantee all server copies were erased.

There is no public in-app deletion endpoint or published processing-time SLA. Requests must be handled consistently with applicable privacy laws. See data-handling choices.

Report bugs or security concerns

Email studionakamoto@gmail.com for a security report, or use the support subject for a general problem. Helpful details: Chrome version, extension version, approximate time and timezone, affected ETH/BTC symbol or expiry, error text and safe reproduction steps. Provide screenshots only after removing names, emails, tokens, cookies, account details and positions.

Do not probe accounts or systems you do not control. We have not published an issue-response SLA or bug bounty. See FAQ, Terms and Privacy.
