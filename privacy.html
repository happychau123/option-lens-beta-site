Optional local subscriber database

Only if an operator separately creates a test account, the prototype SQLite backend keeps normalized email, a salt and scrypt password hash, a hash of each bearer session token, session expiry, and optional Stripe customer/subscription identifiers, subscription status and expiry. Signed billing webhook event IDs can be stored to prevent event replay; no real checkout is configured by this product.

Sessions expire after seven days. There is no automatic retention limit for account or subscription records in the prototype. Account deletion through the administrative CLI removes the account and associated session rows; billing event identifiers can remain without their former account association. Host logs, backups, disaster recovery copies and their retention depend on the eventual deployment and have not been specified or audited. We cannot promise immediate removal from all backups.

Purposes, parties and disclosure

The extension retrieves indicative public market data, stores an asset preference and, only for local development sign-in, requests authentication and an entitlement state. Chrome/Google manages browser extension storage, Binance handles market API requests and the optional local API processes account records. A subscription provider would be involved only if separately configured; the prototype has no live payment flow.

No sale of personal information, behavioral ad targeting or trading-account data collection has been implemented in the reviewed source. We cannot represent the data practices of Binance, Chrome, operating systems, or any future hosting provider. Location of processing, legal basis, cross-border transfers, cookies/logs and any third-party processors require a separate pre-launch review.

Access, correction, deletion and your choices

  1. Free, anonymous use: sign-in is not required. Disable or uninstall the extension through Chrome to stop further requests and remove extension-side storage.
  2. Local test account: sign out in the popup, then use the account request procedure to ask for access, correction or deletion. Uninstalling alone cannot delete records maintained by a separate local backend.
  3. Identity check: make the request from the email used for your test account. Support may request a further control-of-account check; do not provide a password, secret or government identity document by ordinary email.
  4. Deletion execution: an authorized operator verifies and uses the local account-deletion CLI; support confirms the outcome and discusses any applicable backups or retained event IDs. No unattended deletion form or response-time guarantee currently exists.

Any mandatory rights or processing deadlines under applicable law take precedence; their scope depends on your location and the actual operator. For details and security reporting, see Support.

Safeguards, age and future changes

The prototype hashes backend passwords and session tokens and restricts popup account operations to the extension context. These controls do not amount to a security audit. The current loopback HTTP URL is for local development, not a safe remote production sign-in. Do not operate a real subscriber service with this configuration. Option Lens is not directed at children.

Before public deployment, this notice must reflect verified hosting, data retention, deletion and incident response, and any payments/analytics integrations. We will revise public copy before inviting users to a hosted beta. See also Terms and FAQ.
